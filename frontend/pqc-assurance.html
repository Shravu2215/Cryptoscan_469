TASK: FIX and REBUILD the "Runtime Analysis" feature in CryptoScan so it works end-to-end on ANY real website. The previous implementation does not work properly. First inspect the existing code (frontend /scan page, backend-core routes, DB schema, how static findings are stored/rendered, and whatever runtime code already exists) and REPLACE the broken parts rather than stacking on top. Keep it SIMPLE.

HARD RULES
- NO mock / dummy / predefined / sample data. Every finding comes from a real observed event or a real probe. Zero events => honest empty state ("0 crypto operations observed"). Nothing specific to any one site is hardcoded.
- Metadata only: algorithm, operation, key size/curve/mode, hash, caller script URL:line, timestamp, count, URL scheme+host. NEVER capture keys, plaintext, passwords, tokens, cookies, headers, request/response bodies or argument values.
- Reuse the existing Findings, CBOM, Risk Analysis, Quantum Threat Model and Migration Plan pages and the existing static-scan classifier (quantum status, severity, PQC recommendation). No parallel result pages, no second classifier.
- Reports say "observed during this session", never "complete".

USER FLOW (this exact flow must work)
1. On CryptoScan /scan, the user clicks the "Runtime Analysis" card, enters the target URL, clicks "Prepare Session". Backend creates a session. CryptoScan hands {sessionId, ingestUrl, token, targetOrigin, cryptoscanOrigin} to the Chrome extension and shows "Session ready - open the target site". Also open the target URL in a new tab.
2. On the TARGET website, the extension injects a small floating circular widget (bottom-right, closed Shadow DOM so site CSS cannot break it, draggable). It shows state, a live "N events" counter, and Start / Stop buttons. Before Start it shows "Ready". 
3. The user presses Start in the widget. Recording begins: widget shows a spinning ring + "Recording…" + live counter. The user then uses the site normally (click around, log in, chat, upload, etc.). Recording must survive navigation and reloads within the target origin (state kept in chrome.storage.session, widget re-injected on each page load, hooks injected at document_start on every load).
4. The user presses Stop in the widget. The extension flushes remaining events, calls backend /stop, widget shows "Analyzing…", then the extension focuses the existing CryptoScan tab (or opens one) and navigates it to /findings?runtimeSession=<id>. Findings page loads that session's results with Source = Runtime. CBOM, Risk Analysis, Quantum Threat Model and Migration Plan then show this session's data through the existing pipeline.
5. The CryptoScan /scan page must also be able to show the live counter and a Stop button for the active session (backup path), but the widget on the target site is the primary control.

BACKEND (backend-core)
- POST /api/runtime/sessions {targetUrl} -> {id, ingestToken, startedAt}
- POST /api/runtime/sessions/:id/events (batch of aggregated events; token in header; CORS enabled for this route; size cap; reject unknown fields)
- GET  /api/runtime/sessions/:id -> {status, eventCount, lastEventAt}
- POST /api/runtime/sessions/:id/stop -> marks stopped, runs probes, generates findings
- Aggregate by (source, algorithm, operation, keyInfo, callerScript/host). Pass each aggregated event to the existing classifier. Store in the same findings tables with source="runtime" and sessionId.
- Real TLS probe on Stop, only when the target is a public HTTPS host: negotiated TLS version, cipher suite, certificate key type/size, signature algorithm, expiry, and accepted protocol versions (try TLS 1.0/1.1/1.2/1.3 handshakes). Findings: e.g. TLS<=1.1 accepted, RSA/ECDSA certificate or ECDHE key exchange = quantum-vulnerable. If the target is http:// or localhost, create NO TLS result; instead create the finding "Unencrypted transport (no TLS) observed" from the observed HTTP requests below.
- Classification examples (through the existing classifier, no new tables): Math.random / Python random -> informational "non-cryptographic PRNG (only a risk if used for security values)"; MD5/SHA-1 -> broken hash; SHA-256/384/512 -> info (Grover only); AES -> check mode (flag ECB); RSA <2048 high, RSA/ECDSA/ECDH/Ed25519/secp256k1 -> quantum-vulnerable; wallet signing methods -> ECDSA secp256k1.

CHROME EXTENSION (MV3), folder /runtime-extension
- host_permissions: <all_urls>. A background service worker holds session state and does ALL network calls to CryptoScan backend (this avoids page CORS, CSP and mixed-content problems). Add the CryptoScan frontend and backend origins to the manifest so the handoff and fetch work from an https Vercel page to an http://localhost target.
- A content script on the CryptoScan origin (match pattern configurable, must match the deployed Vercel domain exactly) receives the session handoff via window.postMessage and answers a "is the extension installed" ping, so /scan can show "Extension detected" or clear install instructions. 
- Main-world hook script registered with chrome.scripting.registerContentScripts (world:"MAIN", run_at:"document_start", all_frames:true, matches <all_urls>) so hooks run before page code. Hooks only SEND events while a session is active for that origin; otherwise they do nothing.
- Hooks (always call through to the original, never change behavior, try/catch everything):
  * crypto.subtle: digest, generateKey, importKey, exportKey (format only), encrypt, decrypt, sign, verify, deriveKey, deriveBits, wrapKey, unwrapKey -> algorithm name, length, namedCurve, hash, modulusLength.
  * crypto.getRandomValues, crypto.randomUUID, Math.random (aggregate counts; fires very often).
  * fetch, XMLHttpRequest, WebSocket, EventSource -> record only URL scheme + host + port + whether cross-origin (never path query, headers or bodies). Used for "unencrypted HTTP/WS transport" and "third-party host" findings.
  * window.ethereum.request -> method name only, mapped to ECDSA secp256k1.
  * WebAssembly.instantiate / instantiateStreaming -> "WASM module loaded (possible embedded crypto, not analyzable)".
  * Detect loaded JS crypto libraries via globals/script URLs (CryptoJS, forge, sjcl, jsrsasign, elliptic, tweetnacl, ethers, web3) -> "library present".
  * Caller attribution: new Error().stack -> script URL:line; classify first-party vs third-party by hostname.
- Main world -> content script via window.postMessage -> service worker aggregates and flushes every 1s and on stop/pagehide. Fail silently.
- Debuggability (this was the main failure before): extension popup shows session state, event count, last flush time and last error; console.log prefixed "[CryptoScan]" at every stage (handoff received, hooks installed, first event, flush ok/failed, stop). Add a "Self-test" button in the popup that triggers one crypto.subtle.digest and one Math.random call on the active tab and confirms they appear in the counter.
